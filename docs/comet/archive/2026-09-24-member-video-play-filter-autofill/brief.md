# Outcome

播放量筛选开启后，作者主页视频列表在「过滤后可见内容填不满当前页面」时自动继续翻页加载，直到可见内容铺满页面，或作者视频已全部加载完毕；不再需要用户上下反复滑动才能刷出新内容。

# Scope

- 改造 `MemberVideoCtr`（`lib/pages/member_video/controller.dart`）的自动补载：过滤开启且未到底时，只要过滤后可见内容不足以铺满当前页面，就自动请求下一页并重新过滤，直到铺满、到底、请求失败、无新数据或达到安全上限。
- 补载触发不再只依赖「过滤后一条都不剩」：覆盖「过滤后只剩少量条目、填不满一屏」的情况（当前这类情况只靠最后一项被构建出来才触发 `manualLoadMore`，而填不满一屏时最后一项不会被构建，导致停住）。
- 可见内容铺满页面后停止自动翻页，恢复现有手动上拉加载。
- 连续自动翻页达到安全上限后暂停，并给出可理解的提示，用户可手动继续。
- 保留现有过滤判定、筛选弹窗、空态与到底提示。
- 新增覆盖「填不满一屏自动补载 / 铺满即停 / 到底即停 / 上限暂停」的测试。

# Non-goals

- 不改筛选条件本身（播放量区间、已观看两个开关、`shouldHide` 判定）。
- 不改筛选弹窗 UI 与确认 / 取消语义。
- 不过滤未开启时的加载行为保持原样（仍由尾项触发 `onLoadMore`）。
- 不改服务端接口与分页参数（`MemberHttp.spaceArchive`）。
- 不改搜索页或其他页面的列表加载。
- 合集（`season`）类型无分页，不在本次范围内。

# Acceptance examples

- A1 过滤开启且过滤后可见内容不足以铺满当前页面、且未到底时，列表自动请求下一页并重新过滤，无需用户上下滑动。
- A2 自动补载持续进行，直到可见内容铺满当前页面后停止；此后恢复手动上拉加载，不继续自动请求。
- A3 自动补载在作者视频全部加载完毕（`isEnd`）时停止；若一条可见内容都没有，显示现有「没有更多了 / 调整过滤条件」空态。
- A4 单次自动补载连续翻页达到 50 页上限后暂停，不再继续自动请求，并给出可理解的提示；用户手动上拉后可继续加载。
- A5 请求失败或一页没有带来新数据时停止自动补载，不形成请求风暴。
- A6 过滤未开启时加载行为不变：仍只在滚动到尾项时加载下一页，不自动连翻。
- A7 过滤判定 `shouldHide`、筛选弹窗与现有单测不被破坏，继续通过。

# Constraints and invariants

- 「加载完毕」以现有 `isEnd` 为准：视频类型取接口 `hasNext == false` 或返回空列表，其他分页类型取 `next == 0` 或返回空列表。
- 自动补载必须串行：同一时刻只有一个补载循环，复用 `isLoading` / `isEnd` 守卫，保留「无进展即停」保护。
- 安全上限按「一次自动补载连续请求的页数」计，上限 50 页（每页 20 条，约 1000 条）。
- 定位上次观看（`isLocating`）期间不触发自动补载。
- 内部数值与过滤字段保持不变。

# Decisions

- 工作区：当前目录（`current`），沿用 `main` 分支；创建时工作区干净且无其他活跃 Native change。
- 能力归属：本 change 作为已有 `member-video-filter` 能力的增量（关联草稿由 Runtime 检索给出，high）。
- 触发条件：填不满一屏才自动翻页。过滤后可见内容不足以铺满当前页面时自动翻页，铺满后停止并恢复手动上拉。选择理由：这正是「底部没显示完就停住、要反复上下滑」的场景，同时避免对高产作者无界连翻。
- 安全上限：设 50 页上限。连续自动翻页达到上限后暂停并提示，用户可手动继续。选择理由：接口异常或超长列表时避免无限请求，同时仍覆盖绝大多数作者。

# Verification expectations

- 单测：自动补载在「过滤后非空但不足一屏」时继续请求、铺满后停止、到底停止、无进展停止、达到 50 页上限停止。
- 现有测试：`test/pages/member_video/video_filter_test.dart` 与 `member_video_filter_dialog_test.dart` 继续通过。
- 静态检查：改动文件 `dart analyze` 无新增问题。
- 人工：作者主页设置最小播放量（如 100 万），过滤后只剩少量视频时，列表应自动继续加载直到铺满或提示已到底，无需上下反复滑动。
