# 一起看（VideoTogether 兼容）

一起看允许多个客户端在同一房间同步观看 B 站投稿和番剧。协议兼容目标是
[VideoTogether](https://github.com/VideoTogether/VideoTogether)，PiliPlus 侧独立实现传输、会话和播放器接入。

## 使用

1. 从“我的”页顶部的“一起看”入口创建或加入房间；各端使用相同服务器、房间名和密码。
2. 创建者打开投稿或番剧后，成员会收到房间视频。默认弹出 5 秒倒计时确认，可以取消或立即进入。
3. 视频简介操作栏的“一起看”位于分享按钮右侧。默认未加入房间时隐藏，加入后始终显示。
4. 房间页面可发送文字消息、手动打开房间视频、退出房间和修改双向控制选择。

“设置 → VideoTogether”可配置服务器、文字消息显示名称、倍速同步、等待成员缓冲、房间密码保护、
进度校正阈值及入口可见性。服务器更改只影响下次创建或加入，其他设置保存后生效。

视频打开策略有四档：始终自动进入、仅在视频页自动切换、从不自动进入、倒计时弹窗确认（默认）。
取消后同一视频不重复提示，直到房间视频、设置或会话改变；手动“打开房间视频”始终直接打开。

## 控制与兼容边界

- 同步播放、暂停、进度、倍速、投稿分 P、番剧剧集和视频切换。播放中默认校正阈值为 0.5 秒；
  暂停或等待缓冲时使用 0.1 秒阈值。暂停的房间不会仅为同步而初始化未启动的播放器。
- 房间页“双向同步控制”默认开启，适用于全部客户端都支持“最后操作者接管”的房间。
  本地播放、暂停、拖动、倍速和切换视频都可尝试取得控制权。
- 与官方浏览器插件、旧版或其他不支持控制权交接的客户端同房时应关闭双向控制。
  关闭后，普通加入者只跟随；创建者或曾持有控制权者被接管后自动跟随，之后可通过本地操作重新接管。
  若出现“其他房主正在同步”或反复抢控，也应关闭双向控制。
- 官方协议没有可靠的成员身份/能力列表，界面只显示服务端提供的人数，不推测客户端类型或自动切换兼容模式。
- 等待成员缓冲使用服务端聚合的缓冲标记，让控制者和未卡顿成员暂时等待；它不赋予普通成员任意控制权。
- 不支持语音、EasyShare、M3U8 中继、媒体代理或非 B 站页面的原生播放同步。
  [Bili SyncPlay](https://github.com/sky1wu/Bili-SyncPlay) 使用不同协议，不能直接作为本实现的服务器。

## 服务器与隐私

默认地址为 `https://vt.panghair.com:5000`，可以改为自建或其他 VideoTogether 兼容服务。
公共服务由第三方运营，其可用性不由 PiliPlus 保证。只有创建/加入房间或主动测试服务器时才发起相应连接。
媒体由每个客户端直接从 B 站获取，同步服务不转发媒体流或 B 站登录 Cookie；各端仍需具备相应播放权限。
服务器会接收房间名、房间口令、视频页面 URL/标题、播放与缓冲状态，以及发送的文字消息及显示名称。
请使用可信服务，房间密码不要复用其他账号密码。HTTP 地址不提供传输加密，优先使用 HTTPS。
房间密码仅保存在活动会话内存中；可导出的设置保存在既有 Hive setting box，包含上次房间名但不包含密码。

## 代码与协议约定

修改协议、播放器接入或房间生命周期时，应同步本文件和相关测试。
上游贡献分支只保留功能、测试和使用/维护说明；fork 专用的包名、签名与分发工作流保留在开发构建分支。
提交审阅构建时，应标明其源提交及与 PR 的配置差异，确认功能源码一致；空 tag CI 只上传 artifact。

- `lib/services/video_together/`：协议模型、WebSocket 客户端、同步策略和会话管理。
- `lib/pages/video_together/`：房间/设置页面、导航展示及 `PlPlayerController` 适配器。
- 会话依赖抽象播放接口，导航通过回调注入；底层播放器不依赖房间服务。
- 未加入房间时不进行同步或控制权检测。换源串行化、异步 seek 完成语义和 PiP 生命周期修正属于共享
  播放器路径，也会影响普通播放，应同时验证未入房场景。

WebSocket 路径为 `/ws?language=zh-cn`，消息外层为 `{"method": "...", "data": {...}}`。
支持 `/room/update`、`/room/join`、`/room/update_member`、`send_txtmsg` 和 `replay_timestamp`；
成员缓冲字段须保留官方拼写 `isLoadding`，房间等待字段为 `waitForLoadding`。未知消息忽略。
默认每 400 毫秒观测本地操作，控制端和跟随端分别约每 2 秒上报状态；接收广播后立即应用最新状态。

控制端独占服务端 `tempUser` 写权；接管需更换身份，失去写权后以新 WebSocket 作为成员重新加入。
本地媒体切换在重置 Player 前登记夺控意图，发布 URL 不等待拉流；服务端确认对应修订后才清除意图。
禁止所有成员持续写入房间，禁止通过昵称或伪造聊天握手猜测兼容性。

四时间戳偏移：`((serverReceive - localSend) + (serverSend - localReceive)) / 2`。
播放目标：`currentTime + (serverNow - lastUpdateClientTime) * playbackRate`；
暂停和缓冲等待期间直接对齐 `currentTime`。加入/更新确认先用往返中点初始化偏移，再用四时间戳精化。

会话、连接、媒体加载和导航均使用代际标识，异步结果必须校验所有权；跟随队列只保留最新房间修订。
远端命令执行期间和结束后抑制本地操作检测，避免回声抢控。视频页先绑定可准备的适配器，远端播放时
主动初始化 Player、拉流并纠正播放状态；不得仅相信界面缓存状态。
换源串行执行，旧 open/seek 不得影响新媒体；seek 的 Future 必须等待真实操作完成或被取代，
缓冲等待与 duration 等待分别有 5 秒和 8 秒上限。

普通后台挂起同步检测；真实 PiP 或明确开启的后台播放维持会话。自动 PiP 仅有 3 秒过渡豁免。
切网、恢复前台或消息静默 8 秒后重新连接；退避为 1、2、4、8、15 秒，无网络时停止定时重连。
重连先 `/room/join` 取权威快照，再恢复播放和尝试恢复写权；播放流恢复失败不得拆掉健康的 WebSocket。
离开会话必须先使代际失效，再释放订阅、计时器和连接。
