# 目标

在设置中新增一份全局「屏蔽画质」多选列表：被勾选的画质从播放路径的画质选择中剔除，下载路径不受影响。自动选档跳过被屏蔽的画质：

- 用户允许更高一档且视频确实提供时，用更高帧率的同档画质（屏蔽 1080P 高码率后，视频提供 1080P60 帧则用 1080P60 帧）；
- 被屏蔽画质本会被选中时，改选下一档可用画质（只有 1080P 高码率可用时选 1080P 高清，而不是高码率）；
- 剔除被屏蔽项后无可用项时，退回未屏蔽时的原结果，播放不中断。

# 范围

- 设置项与持久化：新增 `SettingBoxKey.blockedVideoQualities`、`Pref.blockedVideoQualities`，设置页入口复用现成的 `MultiSelectDialog`。
- 播放自动选档：`PlayUrlModel.findAvailableVideoQuality` 增加可选屏蔽集合参数；`VideoDetailController.setupFullScreenQualitySwitch` 的半屏 → 全屏选档改调同一方法。
- 播放器两处手动画质菜单（底部控制栏弹窗 `lib/plugin/pl_player/view/view.dart`、全屏「选择画质」BottomSheet `lib/pages/video/widgets/header_control.dart`）不再列出被屏蔽画质，统一从 `VideoDetailController.selectableVideoFormats` 取列表。
- `VideoDetailController.findVideoByQa` 找不到目标画质时的兜底首个画质跳过被屏蔽画质。
- 下载路径保持现状：`lib/http/download.dart` 调用 `findAvailableVideoQuality` 时不传屏蔽集合，下载面板「目标画质」下拉仍列出全部画质。
- 纯 Dart 选档逻辑的单元测试。

# 非目标

- 不改动直播画质枚举 `LiveQuality`。
- 不改动 `VideoQuality` 枚举的 `code` / `desc` / `shortDesc`。
- 不做画质偏好权重或排序（只做「跳过」），也不按网络分别维护屏蔽列表。
- 不屏蔽下载：下载面板下拉、下载选档、下载记录均保持现有行为。
- 不为「当前默认画质正好被屏蔽」增加运行时提示或拦截，只是自动选档时自动降档。
- 不重做 `findAvailableVideoQuality` 既有的「无候选时取候选集最大值」兜底，只在其上叠加屏蔽过滤。

# 验收示例

- A1：屏蔽列表为空时，播放与下载的画质选择结果与当前版本完全一致（回归）。
- A2：屏蔽 1080P 高码率（112），视频可用画质含 1080P60 帧（116）、112、1080P（80），用户首选画质 ≥ 116 时，实际播放 1080P60 帧。
- A3：屏蔽 112，视频可用画质含 116、112、80，用户首选画质为 112 时，实际播放 1080P（80）。
- A4：屏蔽 112，视频可用画质为 112、80（无 116），用户首选画质 ≥ 112 时，实际播放 1080P（80）。
- A5：屏蔽 112，视频可用画质含 116、112、80，用户首选画质为 80 时，实际播放 1080P（80）——屏蔽高码率不会把用户升档到 1080P60 帧。
- A6：屏蔽 112，视频可用画质为 112、116、80，用户首选画质为 80，且 80 恰好不在视频流列表中时，兜底画质不是 112。
- A7：剔除被屏蔽项后候选集为空（例如屏蔽 80 且用户首选画质 ≤ 80）时，退回未屏蔽时的原结果，不崩溃、不出现无流可播。
- A8：半屏 → 全屏切换的自动选档同样跳过被屏蔽画质。
- A9：多个画质可同时屏蔽；同时屏蔽 112 与 116 且两者都可用时，选到 80。
- A10：播放器底部控制栏画质弹窗与全屏「选择画质」BottomSheet 都不列出被屏蔽画质，仍可列出当前实际播放画质及其它可用画质。
- A11：设置页可勾选 / 取消勾选屏蔽画质，保存并重启后选择保留。
- A12：设置项副标题按画质档位从高到低展示已屏蔽画质；未屏蔽时显示「未屏蔽任何画质」。
- A13：下载面板「目标画质」下拉仍列出全部画质；对一个同时提供 1080P60 帧与 1080P 高码率、且用户首选 112 的视频下载，目标画质仍是 112。

# 约束与不变量

- 屏蔽集合为空时，`findAvailableVideoQuality` 与 `setupFullScreenQualitySwitch` 的行为必须与当前版本逐分支一致，不得借机改变现有选档语义。
- 播放不中断优先于屏蔽：任何情况下都要返回一个可播放画质。
- 屏蔽只影响「选哪个画质」，不改码率、解码格式、CDN、音质逻辑。
- 下载链路完全不受屏蔽影响。
- 现有单元测试与 `flutter analyze` 保持通过，不引入新增告警。

# 决策

- 选档语义：被屏蔽画质从候选集剔除后，仍在原选档规则内取「不超过用户首选画质的最高可用档」；首选 ≤ 视频最高可用时走 `acceptQuality` 最近分支，首选 > 最高可用时走「最高可用档，被屏蔽则退到不超过它的最高未屏蔽档」，两个分支都先剔除被屏蔽项。
- 无候选兜底：剔除被屏蔽项后候选为空时，直接使用未屏蔽时的原分支结果。
- 数据流：单一全局 `Pref.blockedVideoQualities`（`Set<int>`，画质 code）；自动选档显式传参，手动画质菜单从 `VideoDetailController.selectableVideoFormats` 取，两处菜单共用。
- 设置入口放在视频设置页画质分组（全屏蜂窝网络画质之后），标题「屏蔽画质」，复用 `MultiSelectDialog<int>`，选项来自 `VideoQuality.values`。

- `flutter test`：新增纯 Dart 选档逻辑单元测试覆盖 A2–A7、A9，原有测试不回退。
- `flutter analyze`：无新增告警。
- 人工核对：设置页勾选「1080P 高码率」后，打开同时提供 1080P60 帧与 1080P 高码率的视频，播放器实际播放 1080P60 帧；打开只提供 1080P 高码率的视频，实际播放 1080P 高清；两次播放器画质菜单中都看不到「1080P 高码率」；下载面板目标画质下拉仍能看到它。
