# V1a Smart CDN 实现记录

日期：2026-10-01。基线：c102a6115c7ac040f6a0c6a1653944b81b82dcb4。
阶段结论：V1a 代码、策略测试与 Windows 原生 EDL 冒烟已实现；这是默认关闭的实验功能，不是已证实海外播放提速的发布版本。

## 使用
设置 → 视频设置 → 播放加速 / Streaming Accelerator。OFF 为默认值；Auto 和 Smart CDN 在 V1 使用同一策略。保存后在下一次视频/画质加载时生效。Multi-Range、Multi-CDN 尚未开放。
诊断页输出最近一次会话的 host、buffer 秒数、bits/s、TTFB、错误、冷却与切换次数，不输出签名 URL。DNS/connect/RTT 不测量，不伪造为 0。

## 实际实现
- 保留当前视频/音频原始 URL、playurl 备选；仅为常规 HTTPS upos 路径补充现有 CDNService 镜像。签名 query 不改。特殊 302/mcdn/IP/Akamai donor 不拼接。
- 每轮一个当前线路、一个挑战线路，顺序发送至多两次 256 KiB 真实 Range 请求；并发为 1。仅接受边界和正文长度匹配的 206，不将 200 全文件响应当测速样本。
- 验证两个成功响应的总长度与 SHA256 前缀一致；出现资源不一致时冷却该候选、不切换。
- 吞吐包含 TTFB；采用时间加权 fast/slow EWMA 的保守值。mpv cache-speed 换算为 bits/s，仅作为辅助合计指标，不声称能从它得到精确逐轨下载吞吐。
- 连续低 buffer 5 秒且吞吐不足才探测；低阈值 8 秒、恢复阈值 20 秒；码率 × 1.5 × 倍速为辅助需求。未知视频码率可按验证的总字节/时长估算，音频未知时仍有估计误差。
- 探测间隔至少 30 秒、切换冷却 45 秒、候选失败冷却 30 秒、每会话至多 4 次切换；候选增益至少 1.5 倍。当前线路探测失败而备选成功也可触发切换。
- seek/network-change 取消旧探测并推进 generation；暂停/缓冲健康停止额外探测；手工与自动探测共用串行队列，手工测速占用期间自动探测让路。
- 对原 Media 的精确 URL/EDL token 替换，不重建 EDL directive。保留分离音频、选轨、字幕选择、播放位置、倍速与暂停意图。切源失败尝试恢复先前 Media，再一次性恢复原始线路并停用本会话；两次 403 可通知上层重新获取 playurl。
- Player.open 切源本身是重开媒体操作，不保证无缝；网络请求超时有强制关闭，播放器切源 Future 超时不能证明底层异步操作已经中止，需实机验证竞态。
- OFF 在创建 client/timer/connectivity subscription 前退出。下载、直播、FileSource、DLNA URL 和原 CDN 设置没有接入新策略。未改 native fork、依赖版本或全局 TLS 行为。

## 验证边界
完整执行记录、原始输出与哈希见 v1/VERIFICATION.txt 与 logs/。基线和改后均使用同一专用 SDK/cache 的原项目 common patches。Windows pub get 已完成依赖解析但插件符号链接步骤报需 Developer Mode；没有改 OS 配置。测试用已有 package_config 执行 --no-pub，不等价于桌面 App 完整构建。

本地覆盖：真实 localhost HTTP Range 验证、取消/超时、健康时不探测、OFF、EWMA/冷却/增益、seek generation、双 403 刷新、资源错配、音频保留、UI 保存回调。
原生测试：固定 fork 的 media_kit + 项目指定 mpv DLL，对合成 AVI + 独立 WAV 的 EDL 读取、30 秒 seek、精确切源、暂停和 1.25 倍速进行 headless 冒烟。native_event_loop DLL 从原插件编译，仅用于测试环境。

尚未验证：真实 Bilibili DASH、登录受限/付费视频、硬件解码、HDR/杜比、多字幕、PiP、投屏、后台/锁屏、网络切换、长期播放、APK/IPA/桌面打包，以及日本网络实际吞吐与缓冲改善。UI 回调测试不等价于 Hive 存储实机重启测试。

Windows：完成 headless DLL/EDL 冒烟，未完成可视桌面完整构建与渲染/硬解验证。
Linux/macOS：Dart 算法可移植，原生插件 ABI、选轨、后台、打包均待 CI/实机检查；不推断 Windows 结果能证明它们兼容。
